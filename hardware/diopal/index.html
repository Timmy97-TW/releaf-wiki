Summary

Twenty‑four cultures under six defined light conditions at once: green light to induce protectant production, red to halt it.

It took three design‑build‑test‑learn cycles. Prototype 2 measured 40 LEDs one by one: the green parts varied by 26% and the red by 22%, and matching them in fours brought each group within 0.4–1.8%. Matching alone did not separate the intensity tiers, so the LEDs are only matched to each other and the low, mid and high levels are set by PWM in code. Prototype 3 enclosed the array; overnight on a shaker a post snapped and the white holder leaked light between wells.

The instrument is built and characterized. Its first culture run, on 19 September 2026, grew in all six arms (3.1), but light leaked between wells, so it is not a light‑dose result. The fixes from that run are not yet re‑tested, the intensity test the array was built for has not been done, and every reading on this page is in lux, which is weighted for human vision and is not a biological light dose until it is converted to photon flux.

LPA: Light Plate Apparatus

The LPA is a 24‑culture LED array designed to test how wavelength and light intensity affect our CcaS/CcaR optogenetic system in engineered Bacillus subtilis. It was designed around B. subtilis 168 and first ran on B. subtilis WB800, the protease‑deficient strain the bioreactor moved to in October (bioreactor, 2.2). Red and green LEDs are arranged across six light conditions, with four replicate cultures per condition.

Through three design–build–test–learn cycles, we improved LED consistency, reduced light leakage between wells, and moved intensity control into software using PWM. The final enclosed design provides controlled, repeatable illumination for optogenetic testing.

Our optogenetic system depends on light intensity and wavelength. We therefore built the Light Plate Apparatus to expose multiple samples to defined red and green light conditions while minimizing variation between wells.

Intensity is controlled through pulse‑width modulation from an Arduino, with one MOSFET assigned to each intensity tier. Once a condition is set, the output remains fixed throughout the run so the LPA provides repeatable illumination rather than adjusting light dynamically.

The array itself, six columns of four with the MOSFET that drives each pair, is drawn in 4.2 Light Layout.

Engineering Cycles

Three design–build–test–learn cycles, from the first array on a breadboard to the enclosed, software‑controlled instrument. The three prototypes follow in order.

2.1 DBTL Cycle 1 – Dual‑Wavelength Array

One green and one red LED per column

  1. DDesignA green and a red LED per column

Design

Each column carries a green and a red LED, so the wavelength can be switched quickly to exercise on and off control of protectant production. Nothing is calibrated at this stage: the aim was to confirm that the array drives both channels under software control.

Build

Each column carries a dual LED, so its output can be switched from green to red. Wire‑management prints were included from the start, since the harness is otherwise difficult to route at this density.

Test

The first dual‑wavelength array powered up and both LED channels switched on and off under software control. The light output was inconsistent across wells, which matters because an intensity comparison needs equal output within a condition.

Learn

The first prototype confirmed that the dual‑wavelength concept was feasible, but it also revealed a source of variation that had to be addressed before the light conditions could be compared reliably.

LED output was inconsistent

Individual LEDs in different wells produced different light intensities even when driven at the same setting. This meant that our low, mid, and high intensity levels were not yet consistent across the array, making comparisons between conditions unreliable.

Design

Prototype 2 addressed the variation between wells. We measured every LED individually and grouped LEDs of similar output into matched sets.

Build

Every LED was driven at 5 V and measured individually on a light meter in a printed sensor fixture, so each reading was taken at the same distance and orientation.

Test

We measured all 20 green LEDs and all 20 red LEDs individually at 5 V, then sorted them into matched groups of four based on output. After rewiring, the six channels formed the low, mid, and high conditions for each wavelength.

Learn

Matching reduced the variation within each group. Before sorting, the green LEDs varied by 26% and the red by 22%; after matching, the four LEDs within each group differed by about 0.4–1.7% for green and 1.5–1.8% for red.

This showed that LED matching should be used to make each column internally consistent, while the actual low, mid, and high intensity levels should be set through PWM duty cycle rather than LED selection.

Prototype 2 left three limitations: the electronics were exposed, the intensity settings were adjusted by hand, and the culture tubes had no fixed position relative to their LEDs.

Design

Prototype 3 kept the matched LED groups from Prototype 2, but focused on making the LPA easier to operate and reproduce through four key changes.

01 · LPA_Box

Enclosed electronicsA printed outer frame houses the LED wiring and perf board so the electronics are protected and contained.

02 · Arduino code

Intensity in softwareLow, mid, and high light levels are set through PWM values in code rather than by manual adjustment.

03 · Left_C, Right_C

Tool‑free assemblyPrinted slider components allow the LPA to be assembled and disassembled without tools.

04 · Tube_Holder

Fixed tube position and light shieldingThe tube holder keeps each culture at the same distance from its LED, improving repeatability between runs, and covers the tubes from ambient light, so the effect of the green and red light is isolated and the data can be relied on.

Build

Test

During the overnight shaker test one of the printed connection posts on the bottom plate broke off, and several wires came loose and were resoldered.

Learn

Reinforce the base at four points

The overnight run showed that concentrating the load on two mounting points was not mechanically sufficient, so all four screw positions on the bottom plate were used and the joints reinforced.

Block light between neighboring wells

The white tube holder allowed light to scatter into adjacent wells, so it was replaced with a black holder and the wall thickness increased from 2 loops to 4.

Results

3.1 First Culture Run, 19 September 2026

On its first culture run, the LPA grew B. subtilis WB800 under all six light arms to an OD600 of 0.91–1.01 at 24 h, close to the fitted plateau of 1.005.

The Run

On 19 September 2026, B. subtilis WB800 grew in the LPA under its six light arms, red and green each at a low, medium and high intensity (R1–R3 and G1–G3), and was read on a plate reader at five time points up to 24 hours.

Twelve of the 24 wells were loaded: one tube in each red arm and three in each green arm; the other wells stayed empty. By the procedure on the team wiki’s Measurement page, each tube held 2 mL of LB inoculated with the culture and was incubated at 37 °C with shaking; the Digital Twin page notes that the plate’s temperature was not recorded during the run.

This is the overnight shaker run of prototype 3 (2.3): a bottom‑plate post snapped and light leaked through the white tube holder into neighboring wells, so the arms cannot be compared with each other.

Final Design & Specifications

The final LPA combines what the three cycles established: LEDs matched by measured output, intensity set by PWM in code, enclosed electronics, a fixed tube position and a black holder that shields each well.

It lights 24 cultures under six fixed conditions, two wavelengths at three intensities with four replicates each, from one Arduino and three MOSFETs.

4.2 Light Layout

Each column of four is one light condition. A tier is a green column and a red column driven by the same MOSFET, so the two wavelengths at one tier share one duty cycle. The duty cycles are fixed in code before the run, so every tube gets the same light from start to finish.

Why green and red?three reasons
  1. Green turns production on. In the CcaS/CcaR system, green light activates the CcaS sensor, which switches on CcaR and, through it, the production genes.
  2. Red turns it off. Red light switches CcaS back to its inactive form.
  3. One array asks both questions. With both colors at three intensities, one run shows how strongly production follows the light and whether red stops it.
Why match the LEDs and still use PWM?matching evens, PWM sets

Matching cut the spread inside each group from 26% (green) and 22% (red) to 0.4–1.8%, but left the three groups too close together to serve as tiers (2.2). Matching therefore equalizes the LEDs within a condition, and PWM sets the intensity between conditions.

Safety. The LPA runs on 5 V: unplug the Arduino and switch off the bench supply before changing any wiring, and do not look straight into the LEDs at full brightness (the guide’s “Before you start” page). The cultures are B. subtilis, handled at BSL‑1 as set out on the team wiki’s Safety page.

References

Illuminating a plate of cultures from below with per‑well control is the Light Plate Apparatus pattern from the optogenetics literature1, which our LPA follows and is named after. What we added is the dual‑wavelength column layout and LEDs matched by measured output, in an enclosure sized for our own tubes.

The biology is the CcaS/CcaR green/red switch, also from the literature, not designed here; it was characterized in B. subtilis by Castillo‑Hair and colleagues2. This page reports light in lux and does not convert it to photon flux, so our tiers are not placed on that paper’s dose scale.
